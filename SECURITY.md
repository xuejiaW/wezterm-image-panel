# Reporting security issues

Do not attach real session logs, SQLite databases, credentials, cached images,
or unreviewed terminal recordings to a public issue.

If GitHub private vulnerability reporting is enabled, use that channel for
sensitive findings. Otherwise, describe the issue without sensitive details
and ask for a private reporting route. A synthetic reproduction is preferred;
[docs/demo.md](docs/demo.md) provides a safe starting point.

This tool reads local Codex implementation formats and snapshots local images.
Only open logs you trust. Include software versions and a minimal synthetic
fixture in compatibility reports rather than your Codex home directory.
